本書は、現行ソースコード（主に `DokoTsubu2/`）に存在する**ハードコードのうち**、次の観点で「修正検討対象」を抽出したもの。

- **環境依存**: 実行環境（本番/検証/開発、ホスト、デプロイ名、ファイル配置）が変わると壊れやすい
- **運用変更に弱い**: 仕様/構成変更で修正箇所が散りやすい、変更頻度が比較的高い

※ 本書は調査結果の一覧であり、コード修正は含まない。

## 優先度A（本番移行・環境差で即事故り得る）

### DB接続情報が直書き（ホスト/DB名/資格情報）

- **対象**
  - `DokoTsubu2/src/main/java/dao/UserDAO.java`
    - `JDBC_URL = "jdbc:mysql://localhost/dokoTsubu"`
    - `DB_USER = "root"`
    - `DB_PASS = "7358"`
    - （コメントアウト）`jdbc:h2://localhost/dokoTsubu`
  - `DokoTsubu2/src/main/java/dao/MuttersDAO.java`
    - `JDBC_URL = "jdbc:mysql://localhost/dokoTsubu?useAffectedRows=false"`
    - `DB_USER = "root"`
    - `DB_PASS = "7358"`
- **影響**
  - 環境ごとの接続先差分（ホスト名、DB名、認証、オプション）に追随できず、デプロイ先で起動/動作不良になりやすい。

### 開発者PCの絶対パス固定（環境が違うと読めない）

- **対象**
  - `DokoTsubu2/src/main/java/model/AiConfigLoader.java`
    - `DEFAULT_CONFIG_PATH = Paths.get("/Users/takashioikawa/Dev/ai-config.json");`
  - `DokoTsubu2/src/main/java/servlet/Main.java`
    - コメント内に同パスの記載
- **影響**
  - 実行環境のユーザー名/ディレクトリ構成に依存し、設定ファイル読み込みが破綻しやすい。

### デプロイコンテキスト名 `/dokoTsubu` 固定（配布先で404になりやすい）

- **対象**
  - `DokoTsubu2/src/main/java/servlet/SearchMutter.java`
    - `response.sendRedirect("/dokoTsubu/");`
  - `DokoTsubu2/src/main/webapp/WEB-INF/jsp/registerResult.jsp`
    - `<a href="/dokoTsubu">...`
- **影響**
  - WAR名/コンテキストパスが変わると遷移が壊れる（404）可能性が高い。

## 優先度B（変更頻度が高く、修正が散りやすい）

### ルーティング/遷移先の直書き（URLやJSP配置変更に弱い）

- **対象: URLパターン（Servlet）**
  - `Login.java`: `@WebServlet("/Login")`
  - `Register.java`: `@WebServlet("/Register")`
  - `Logout.java`: `@WebServlet("/Logout")`
  - `SearchMutter.java`: `@WebServlet("/SearchMutter")`
  - `UpdateMutter.java`: `@WebServlet("/UpdateMutter")`
  - `DeleteMutter.java`: `@WebServlet("/DeleteMutter")`
- **対象: `web.xml`**
  - `DokoTsubu2/src/main/webapp/WEB-INF/web.xml`
    - `<url-pattern>/Main</url-pattern>`
- **対象: JSP への forward / redirect**
  - `Main.java`, `Login.java`, `SearchMutter.java`, `UpdateMutter.java` など
    - `getRequestDispatcher("/WEB-INF/jsp/...")`
    - `sendRedirect(request.getContextPath() + "/...")`
  - `Register.java`, `Logout.java`
    - `getRequestDispatcher("WEB-INF/jsp/...")`（先頭 `/` なしの相対）
- **影響**
  - 画面/URL設計の変更や JSP 配置変更時に影響範囲が広がり、修正漏れが出やすい。

### SQL直書き（テーブル/カラム/検索仕様変更に弱い）

- **対象**
  - `DokoTsubu2/src/main/java/dao/MuttersDAO.java`
    - `SELECT ... JOIN ... ORDER BY ...`
    - `INSERT INTO MUTTERS(...) ...`
    - `... WHERE ... LIKE ? ...`
    - `UPDATE ... WHERE ...`
    - `DELETE ... WHERE ...`
  - `DokoTsubu2/src/main/java/dao/UserDAO.java`
    - `INSERT INTO users ...`
    - `SELECT * FROM users WHERE ...`
- **影響**
  - スキーマ変更（テーブル名/カラム名/索引/検索要件）に対して修正箇所が DAO 内に散りやすい。

### 外部API仕様・閾値の直書き（運用チューニングやAPI更新に弱い）

- **対象**
  - `DokoTsubu2/src/main/java/model/GeminiApiClient.java`
    - API ベースURL: `https://generativelanguage.googleapis.com/v1beta/models/`
    - HTTP タイムアウト: `Duration.ofSeconds(30)`
    - 表示上限: `MAX_COMMENT_CHARS = 50`
    - 生成設定: `maxOutputTokens = 64`, `temperature = 0.7`
- **影響**
  - 運用上の調整（タイムアウト/生成品質/コスト）や API 更新時に、コード修正が必要になりやすい。

### キャッシュ制御ヘッダの固定（運用方針変更で調整が必要になりやすい）

- **対象**
  - `DokoTsubu2/src/main/java/servlet/UpdateMutter.java`
    - `Cache-Control: "no-store, no-cache, must-revalidate"`
    - `Pragma: "no-cache"`
- **影響**
  - キャッシュ方針（プロキシ/ブラウザ/セキュリティ要件）の変更時に、個別修正が必要になりやすい。

## 対応案（修正方針の候補）

本章は「どのように修正すると環境差・運用変更に強くなるか」の案を列挙する（実装手段はプロジェクト方針に合わせて選択）。

### 優先度Aへの対応案（事故回避を最優先）

#### DB接続情報（URL/ユーザー/パスワード）の直書き

- **方針案**
  - **環境変数化**: `DB_URL`, `DB_USER`, `DB_PASS` を OS/コンテナ/実行ユーザーの環境変数から取得
  - **外部設定ファイル化**: `db.properties` 等を配置し、デプロイ環境ごとに差し替え
  - **JNDI DataSource 化（Tomcat 想定）**: `context.xml` / サーバ設定に寄せ、アプリ側は JNDI 名のみ保持
- **最低限やるべきこと**
  - リポジトリから **資格情報（特にパスワード）を除去**し、平文直書きをやめる
  - `localhost` 固定をやめ、環境ごとに切り替え可能にする

#### AI設定ファイルの絶対パス固定（`/Users/.../ai-config.json`）

- **方針案**
  - **環境変数でパス指定**: 例 `AI_CONFIG_PATH` を見て、未指定なら既定へフォールバック
  - **クラスパス配置**（秘匿値を含まない場合のみ）: `resources` 配下へ置き、環境差を減らす
  - **Webアプリの設定領域へ**: `WEB-INF` 配下や Tomcat の外部設定ディレクトリへ置き、サーバ側でパス固定
- **最低限やるべきこと**
  - OSユーザー名に依存するパスを除去し、環境ごとの指定点を1箇所に集約する

#### コンテキストパス `/dokoTsubu` 固定

- **方針案**
  - **`request.getContextPath()` を常用**し、`"/dokoTsubu"` のような固定値を撤去
  - JSP は `<a href="<%= request.getContextPath() %>/...">` へ統一
  - Servlet は `sendRedirect(request.getContextPath() + "/...")` へ統一
- **最低限やるべきこと**
  - `SearchMutter.java` の `sendRedirect("/dokoTsubu/")` と `registerResult.jsp` の `href="/dokoTsubu"` を解消

### 優先度Bへの対応案（変更に強い形へ寄せる）

#### ルーティング／画面遷移パスの散在

- **方針案**
  - パス定数を **1箇所に集約**（例: `Paths`/`Routes` 的な定数クラス）
  - `getRequestDispatcher("/WEB-INF/jsp/...")` の表記ゆれ（先頭 `/` の有無）を統一
  - `web.xml` と `@WebServlet` の併用方針を明確化（どちらを正とするか）

#### SQL 直書き

- **方針案**
  - SQL を **DAO 内の定数としてまとめる**（文字列の散在を抑制）
  - 将来的には **Mapper/ORM（MyBatis/JPA 等）**でスキーマ変更耐性を上げる（学習用途なら過剰な場合あり）
  - テーブル名・カラム名変更が想定されるなら、少なくとも SQL を 1ファイル（または 1クラス）へ集約

#### 外部API（Gemini）仕様・チューニング値の直書き

- **方針案**
  - `ai-config.json` に **運用パラメータ（timeout/maxOutputTokens/temperature/maxChars 等）**を追加して外出し
  - ベースURL/バージョン（`v1beta`）は、変更時に差し替えやすいよう設定化
  - 失敗時メッセージも設定ファイル側へ寄せ、文言差し替えを容易にする

#### キャッシュ制御ヘッダ固定

- **方針案**
  - `no-cache` 系ヘッダの付与ポリシーを「全体フィルタ（Filter）」へ集約し、個別 Servlet に散らさない
  - 画面/機能単位で差が必要なら、設定（on/off）できるようにする
